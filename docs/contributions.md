# Contribute Data — процесс приёма и научной проверки данных

*Версия 0.1 · 10.10.2026 · раздел сайта `/{en,ru}/contribute/`*

Принцип раздела: **Every outcome matters. Negative results are data, too.** Atlas принимает от исследовательских групп и клиник данные ПГТ-мт — в первую очередь полные циклы и отрицательные исходы, которые публикуются реже успешных.

## 1. Что есть сейчас

| Компонент | Где | Что делает |
|---|---|---|
| Страница Contribute Data | `site/src/pages/Contribute.tsx`, тексты — `site/src/i18n/{ru,en}.ts` → `contribute` | Объясняет зачем, что и как; шаблон; статусы проверки; признание вклада; связь с куратором |
| Шаблон PGT-mt Research Data Submission | генератор `etl/atlas_etl/submission_template.py` → `site/public/templates/PGT-mt_Research_Data_Submission_v1.0.xlsx`, сводка `site/src/data/submissionTemplate.json` | Листы Study, Cycle, Embryos, Samples_Measurements, Methods, Clinical_Outcomes, Data_Dictionary (+ Instructions EN/RU, Lists) |
| Модель статусов | `site/src/lib/contribute.ts` | Submitted → Under review → Validated → Included / Rejected; уровни доказательности; условие показа в графиках |
| Иллюстрация «путь данных» | `site/scripts/sketch/generate.mjs` → `site/src/illustrations/data-pathway.svg` | Подписи — в словарях (`contribute.review.labels`) |

Изменить шаблон: править описание полей в `submission_template.py`, затем `cd etl && python -m atlas_etl.submission_template` и закоммитить xlsx и json (тест `test_committed_files_are_up_to_date` следит за актуальностью; файл побайтно воспроизводим). Новая версия шаблона — новый номер `VERSION`.

## 2. Чего сознательно нет

- **Нет приёма файлов и сервера.** Сайт статический; медицинские файлы на сайт и в GitHub не загружаются. `.gitignore` исключает `submissions/`, `incoming/`, `*.submission.xlsx`.
- **Нет формы обращения.** Пока канал не выбран, блок «Связаться с куратором» честно сообщает, что связь не активирована (`CURATOR_CONTACT.email = null`), и не имитирует отправку.
- **Нет автоматического включения.** Никакой статус не меняется сам; данные попадают в набор только отдельным PR с меткой `data-change` после проверки куратора.

## 3. Научная проверка

Статусы (переходы — только решение куратора):

```
Submitted → Under review → Validated → Included
              └──────────────┴──────→ Rejected (с обоснованием)
```

Уровни доказательности хранятся рядом с каждым значением и не смешиваются без пометки:

1. `peer_reviewed_published` — рецензированные публикации;
2. `published_not_peer_reviewed` — препринты, тезисы, диссертации, отчёты;
3. `unpublished_research_data` — неопубликованные данные групп и клиник;
4. `unverified_report` — непроверенные сообщения; в графиках не показываются никогда.

Для неопубликованных данных до включения обязательно подтверждаются: полномочия исследователя (`authority`), разрешение на использование и показ (`permission`), обезличивание (`deidentification`), этические требования — одобрение комитета и согласие пациентов (`ethics`). Функция `isEligibleForPublicCharts` кодирует это правило и покрыта тестами.

Проверка включает: полноту и внутреннюю согласованность (счётчики цикла ↔ строки эмбрионов, ссылки между листами), пересечение с уже опубликованными данными (поле `overlap_with_published`, защита от двойного учёта), различие «0 / пусто / ниже предела обнаружения», отсутствие прямых и косвенных идентификаторов.

## 4. Признание вклада

Каждое значение сохраняет источник (публикация, авторы, DOI — или группа и организация). Возможны совместные научные публикации; соавторство не автоматическое и определяется по критериям ICMJE для каждой публикации.

## 5. Что нужно для включения настоящего канала связи

Решение куратора (Ilya Mazunin):

1. **Выбрать и подтвердить публичный профессиональный адрес** для научных обращений (например, институциональный адрес или отдельный адрес проекта). В источниках репозитория есть адрес автора для корреспонденции из рукописи и CV — но его использование на сайте как канала Atlas должен явно подтвердить куратор.
2. Записать адрес в `site/src/lib/contribute.ts` (`CURATOR_CONTACT.email`), обновить тест `no address is configured…` в `contribute.test.ts` и e2e-проверку контактного блока — страница сама покажет кнопку `mailto:` с темой `[PGT-mt Atlas] …` и шаблоном письма без данных пациентов.
3. **Выбрать защищённый канал передачи файлов** (институциональное хранилище с шифрованием или аналог) и описать его в ответе исследователю; публичная загрузка на сайт не планируется.
4. Объявить **лицензию набора данных и формат цитирования** (сейчас «будут объявлены»), чтобы исследователи знали условия использования своих данных.
5. По желанию — форма обращения через внешний сервис; требует отдельного согласования (CLAUDE.md: внешние сервисы — только после согласования).
