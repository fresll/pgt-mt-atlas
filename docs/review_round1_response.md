## T1–T2. Фото, SVG и графики в production build

**Воспроизведение.** Сборка проверялась в Chromium (headless) через три сервера:

1. имитация GitHub Pages: сайт под `/pgt-mt-atlas/`, каталог без слеша → 301, нет файла → `404.html` (статус 404), без SPA-подстановки, регистр имён учитывается (`site/e2e/static-server.mjs`);
2. та же папка `dist/`, открытая по другому пути (корень сервера, `python3 -m http.server` в `dist/`);
3. `vite preview` (так запускаются существующие e2e и README).

На исходной версии (`cb43532`) при пути `/pgt-mt-atlas/` все запросы давали 200, фото (`naturalWidth = 720`), SVG и 1/3/2/3 графиков отображались. При другом пути размещения (п. 2) воспроизводилась ровно картина из рецензии:

- `GET /pgt-mt-atlas/img/ilya-mazunin.jpg` → 404 (фото не отображается);
- `GET /pgt-mt-atlas/assets/app-*.css` и `app-*.js` → 404: страница без стилей, inline-SVG без размеров и цвета чернил;
- графики навсегда в состоянии «Загрузка графика…»;
- даже при доступных чанках предзагрузка Plotly шла по зашитому пути `"/pgt-mt-atlas/"+dep` (`__vitePreload`) и проваливалась.

**Установленная причина.** Базовый путь `/pgt-mt-atlas/` был зашит в HTML (`<script>`, `<link>`, `<img>`, ссылки меню), в CSS (`url(/pgt-mt-atlas/assets/*.woff2)`), в путь предзагрузки чанков и в `src` фото (`import.meta.env.BASE_URL`). Любое размещение не по этому пути (свой домен, форк репозитория с другим именем, локальный просмотр `dist/`) ломало фото, стили/SVG и графики одновременно. Регистр имён файлов и HTTP-статусы на правильном пути проблем не показали.

**Исправление (минимально достаточное, без отключения SSG/гидратации и без заглушек):**

| Файл | Изменение |
|---|---|
| `site/vite.config.ts` | `experimental.renderBuiltUrl`: ссылки из JS (предзагрузка чанков) и CSS (шрифты) — относительно самого файла |
| `site/scripts/postbuild.mjs` | в каждом HTML `href/src/content="/pgt-mt-atlas/…"` → относительный путь страницы (`../../…`); сборка падает, если абсолютный base остался |
| `site/src/lib/base.ts` (новый) | корень сайта в браузере = каталог над `assets/` фактического скрипта; при SSG и в dev — base из конфигурации |
| `site/src/main.tsx` | basename маршрутизатора = фактический корень; ссылка на favicon переводится в абсолютную (иначе 404 после клиентского перехода на страницу другой глубины — найдено новым e2e) |
| `Home.tsx`, `About.tsx`, `Curator.tsx`, `Data.tsx`, `Contribute.tsx` | `import.meta.env.BASE_URL` → `asset()` / `<Photo>` |
| `site/src/components/Photo.tsx` (новый) | изображение с сообщением при ошибке загрузки (в т. ч. если ошибка случилась до гидратации) |
| `site/src/components/PlotlyChart.tsx` | при неудачной загрузке модуля Plotly — сообщение `common.chartError` (RU/EN) вместо бесконечной «загрузки» |

Канонический base для GitHub Pages остаётся `/pgt-mt-atlas/` (`ATLAS_BASE`), `404.html` по-прежнему использует абсолютные адреса.

## T3. React #418, маршруты и языковые ссылки

**Воспроизведение.** `vite preview`, прямой вход на `/pgt-mt-atlas/ru/about` (и 3 других адреса без слеша): `pageerror: Minified React error #418`. Причины:
1. на адрес без слеша `vite preview` отдаёт корневой `index.html` (страница выбора языка), клиент рендерит «О проекте» → несовпадение с HTML;
2. сама ссылка переключателя языка в статическом HTML строилась **без** слеша (`/pgt-mt-atlas/en/science/heteroplasmy-landscape`), потому что при SSG `pathname` не имеет слеша; React 19 при гидратации не исправляет атрибут, поэтому пользователь попадал на адрес без слеша.

**Исправление:**
- `Layout.tsx`: `switchLangPath()` — путь другой языковой версии всегда со слешем; query и hash добавляются после гидратации (первый клиентский рендер совпадает со статическим HTML);
- `postbuild.mjs`: первым элементом `<head>` — короткий скрипт, который до загрузки ресурсов заменяет адрес без слеша на адрес со слешем (query и hash сохраняются). Гидратация не отключалась, предупреждения не подавлялись;
- `vite.config.ts`: `vite preview` отвечает 301 на каталог без слеша, как GitHub Pages.

**Проверено:** прямой вход без слеша с `?q=1#content` на 4 страницах через имитацию GitHub Pages и через `vite preview` — адрес нормализован, query/hash сохранены, ошибок консоли нет; ссылки меню и переключатель языка в статическом HTML заканчиваются слешем; переключатель после гидратации сохраняет `?x=1#model-blastocyst`. Модульные тесты: `site/src/lib/routing.test.ts`.

## Найденные расхождения, которые не исправлялись (решение куратора)

1. **Spath et al., 2021**: вариант пациентки C — «m.10191T>G» в абстракте и введении, «m.10191T>C» в результатах, подписи к рисунку и обсуждении. Набор следует основному тексту.
2. **Tofilo 2026, «ICM» = «ICM+»**: по ESM 1 и методам рукописи фракция «ICM» включает прилегающие клетки ТЭ. На сайте добавлено пояснение; категория `icm` эмбрионов 1, 2, 5, 6 не переименовывалась.
3. **Tofilo 2026, средние парные разности рукописи** (+0,707 / −1,410 п.п.) не воспроизводятся ни по xlsx, ни по ESM 2; окончательный текст статьи недоступен.
4. **Граница 30 %**: Newcastle — «менее 30 %», на графиках доли считаются «≤ 30 %». Пояснено в подписи графика; правило подсчёта не менялось.
5. **Ориентир 15–30 % для m.3243A>G**: Ji 2023 приводит его со ссылкой на литературу, собственный порог авторы не определили; первичный источник диапазона не проверялся.
6. **p_эупл 0,5 (35 лет) и 0,3 (40 лет)**: из текстовых оценок Volodyaev 2025 напрямую не следуют; соответствие рис. 2 и учёт мозаицизма должен подтвердить автор модели.
7. **Пунктир P = 0,8 на графиках модели** не объяснён ни в данных, ни в подписи — нужно решение: подписать или убрать.
